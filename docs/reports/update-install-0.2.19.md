# Установка обновлений 0.2.19

## Результаты

Измерен участок от запуска тихого NSIS до завершения процесса и подтверждения `complete`. Скачивание и запуск интерфейса в эти числа не входят.

| Вариант | Замеры, с | Медиана, с | Изменение к прежнему установщику |
| --- | --- | --- | --- |
| Прежняя упаковка 0.2.18 | 171,813 / 164,320 / 167,626 | 167,626 | — |
| Прямая запись небольших файлов, промежуточный вариант | 101,696 / 96,051 / 99,384 | 99,384 | −40,7% |
| Финальный алгоритм, неизменившийся Python | 24,134 / 23,884 / 24,142 | 24,134 | **−85,6%, в 6,9 раза быстрее** |
| Финальный алгоритм, неполная старая среда | 79,307; один замер | — | −52,7% к прежней медиане |

У полного восстановления только один замер; его нельзя выдавать за медиану или гарантированное время первого обновления. Числа относятся к этой машине и этим условиям.

## Условия

Windows x64, NTFS, каталог установки на диске E:, Windows TEMP на C:. Использован один и тот же упакованный payload 0.2.18 и отдельный продукт `Archi Update Benchmark` с отдельным appId. Реальное приложение и пользовательский профиль не менялись. Запуск: `/S /currentuser --updated /D=<изолированный каталог>`, без автоматического открытия приложения и ярлыков. Секундомер — `System.Diagnostics.Stopwatch`; успешный результат требует нулевого кода процесса и статуса `complete`.

После первоначального развёртывания выполнены по три последовательных обновления каждого варианта. Первоначальное развёртывание не входит в медианы; оно совпало с установкой зависимостей разработчика. Во время сравнительных замеров сборки и установка зависимостей не запускались. Дисковый кеш не сбрасывался. Исходные JSON измерений хранятся локально в `.cache/update-install-0.2.19`; все входные данные синтетические.

Для полного восстановления воспроизведён установленный состав старой упаковки без двух служебных ARM64-launcher файлов distlib. Проверка обнаружила неполный состав и выбрала распаковку, а три последующих обновления сообщили `reused`.

## Причина и исправление

Шаблон electron-builder 26.15.3 распаковывал весь пакет во временный каталог, затем копировал его в каталог приложения. Старый деинсталлятор также перемещал и удалял все файлы среды. Основную нагрузку создавали тысячи мелких файлов Python.

В финальном варианте среда хранится отдельным несолидным архивом LZMA2 со словарём 1 МиБ. Если состав, размеры и SHA-256 установленной среды совпадают с манифестом нового пакета, её каталог переименовывается в соседний на том же томе и возвращается после замены приложения. Сначала проверяется состав: неполная среда не требует бесполезного хеширования всех оставшихся файлов. Изменившаяся или повреждённая среда распаковывается сразу в конечный каталог и проверяется перед подтверждением успеха. Повторное использование не применяется к работающему приложению; штатная остановка остаётся за electron-builder.

Простая запись небольших файлов напрямую тоже помогла, но сохранение всей неизменившейся среды дало значительно больший эффект. Произвольное сохранение старого Python только по номеру версии не используется: могли измениться зависимости или содержимое файлов. Бинарные патчи установленного Electron и изменение системного антивируса не применялись.

Отключение неподдерживаемого фильтра ARM64 исправляет пропуск `t64-arm.exe` и `w64-arm.exe` старым Nsis7z. Проверка итоговой установки подтвердила SHA-256 **всех 7 606 исходных файлов**, суммарно 595 404 179 байт. Встроенная среда содержит 7 318 файлов. Дополнительные кеши `__pycache__/*.pyc` допустимы; лишний код, ссылки, отсутствующие и повреждённые файлы исключают сохранение среды. Portable остаётся с обычным готовым Python и собирается с совместимым фильтром BCJ.

Убрана также искусственная задержка 1 с перед закрытием экрана обновления после появления готового окна. Она не входит в приведённый замер NSIS.

## Размер и блоковая загрузка

Сравнительные установщики: 171 186 873 байта до изменения и 174 367 171 после (+1,9%). План настоящего `electron-updater` по их blockmap повторно использует 106 875 194 байта и скачивает 67 491 977 байт (38,7% нового файла). Это расчёт плана для изолированных сборок с одинаковым payload, не измерение сетевой скорости и не размер скачивания опубликованного релиза. Смена упаковки однократно меняет больше блоков; дифференциальная загрузка и полный резервный установщик сохранены.

## Границы проверки

Оформление нативного окна проверено в светлой и тёмной палитрах для подготовки, установки, запуска и ошибки. Проверены системные контрастные цвета и обработка `WM_SETTINGCHANGE` без изменения настроек Windows пользователя. Нативные компоненты собираются штатным .NET Framework 4.

Проверены отказы при повреждении файла с сохранением размера, отсутствии файла и лишнем коде; нормальный кеш Python допускается. Реальная проверка полного дерева выдала 7 318/7 318 и 100% через дополнительный канал прогресса. Процент и остаток относятся к текущему этапу проверки, а не ко всей установке. Для этапов без счётчика показаны название операции, прошедшее время и неизвестный остаток. Устаревшая оценка времени скрывается. Светлое и тёмное окно с каской, русским текстом, процентом и остатком просмотрены визуально.

Измерен тихий режим установки для текущего пользователя. Повышение прав для установки на всю машину, отмена питания, другой диск и другие антивирусные настройки не входят в эти замеры. При прерывании процесса сохранённый каталог может остаться рядом с установкой; полный установщик остаётся пригодным для восстановления.

Изменения упаковки действуют уже при входящем обновлении до 0.2.19. Новое оформление и дополнительные показатели нативного окна используются обновлениями, запускаемыми из 0.2.19 и последующих версий: старая версия запускает свой прежний экран до замены приложения.
