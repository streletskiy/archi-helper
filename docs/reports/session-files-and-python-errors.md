# Разбор ошибок Python и организация файлов чатов

Обобщённые технические рекомендации. Примеры ниже синтетические; они не описывают результаты проверки какого-либо реального проекта или пользовательской сессии.

## Пути и диагностика

Файл, сохранённый как `data.json` в рабочей папке чата, не появляется автоматически в `work/data.json`. Перед обработкой проверьте фактическое расположение входных данных. Ошибка пути не доказывает потерю данных Archicad.

Строка счётчика в stdout означает только прогресс. Причину остановки определяют отдельно по `termination`, `error`, `stderr`, коду завершения и полному журналу. Тайм-аут внешнего исполнителя действует независимо от HTTP-ожидания внутри скрипта.

Полный обход GDL-параметров значительно тяжелее подсчёта элементов. Читайте нужные поля небольшими партиями, сохраняйте промежуточные результаты и указывайте границы выполненной проверки. Успех выбранной партии не подтверждает проверку всего проекта. Нулевой код завершения сам по себе не доказывает отсутствие несоответствий.

## Организация приложения

- У каждого чата есть постоянная отдельная рабочая папка в профиле. Вложения, скрипты, журналы и промежуточные результаты сохраняются там и не смешиваются с исходниками проекта.
- Файловые инструменты по умолчанию используют `scope: session`. Для исходников доступен `scope: project`; Python получает `ARCHI_PROJECT_DIR`, `ARCHI_WORK_DIR` и `ARCHI_LEGACY_DIR`.
- Старые служебные файлы копируются без удаления оригиналов. Непомеченные файлы исходной папки автоматически не очищаются.
- Исполнитель различает завершение, ошибку, тайм-аут, отмену, ошибку запуска и ошибку журнала. В краткой диагностике сохраняется причина остановки, а в полном журнале — вывод процесса.
- По умолчанию Python ограничен 300 секундами; `timeout_seconds` допускает обоснованное увеличение до 1800. Тайм-аут и отмена оставляют потенциально неизвестный результат изменений: перед повтором требуется чтение состояния.

## Папки профиля

```text
%APPDATA%/Archi/
  settings.json
  projects/<projectId>/
    sessions/<sessionId>.json
    workspaces/<sessionId>/
      attachments/
      .archi/
        api/
        results/
        scripts/
        images/
        tmp/
    legacy/.archi/
```

При переопределении профиля используется выбранный каталог. Доступ к реальному проекту нужен только для текущей пользовательской задачи; его имена, идентификаторы, пути, журналы и результаты не переносятся в публикуемые справки или примеры.
