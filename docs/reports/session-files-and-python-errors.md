# Разбор ошибок Python и организация файлов чатов

Дата разбора: 21.10.2026. Источник — сообщения, сохранённые результаты и журналы Python указанной пользователем сессии. При разборе проект Archicad не изменялся. Пользовательские файлы и полная переписка в репозиторий не включены.

## Что произошло

| Сообщение | Причина и последствия |
| --- | --- |
| `FileNotFoundError: ... 'work/zones_poly.json'` | Скрипт сохранил исходную выгрузку в `zones_poly.json` в корне проекта, а при проверке построил другой путь — `work/zones_poly.json`. Файл в корне существует, в `work` отсутствует. Это ошибка выбора пути, а не потеря данных Archicad. |
| `Не удалось выполнить run_python: зон в проекте: 1427` | `зон в проекте: 1427` — обычная строка прогресса перед обходом зон. Процесс завершился с кодом 1 примерно через 301,1 секунды без Python traceback. Старый исполнитель принудительно завершал дерево процессов через 300 секунд; сочетание времени и вывода соответствует этому тайм-ауту. Причину остановки старая версия отдельно не сохраняла, поэтому по одному журналу нельзя абсолютно исключить ручную остановку. |

Во втором случае скрипт пытался считать полные GDL-параметры всех 1427 зон партиями по 120. Это существенно тяжелее подсчёта зон. Его HTTP-ожидание было настроено на 1800 секунд, но внешний исполнитель приложения всё равно ограничивал весь скрипт пятью минутами. Windows завершает принудительно остановленный процесс с ненулевым кодом; прежний код приложения добавлял предупреждение об остановке только при `exitCode === null` и пропускал этот случай.

Затем краткая сводка брала последнюю строку общего вывода и использовала её как текст ошибки. Поэтому полезный счётчик выглядел причиной сбоя. Фрагмент `svg` в сообщении пользователя отсутствует в сохранённом выводе Python; он не относится к диагностике процесса.

## Что удалось проверить в исходной сессии

После ошибки пути следующий скрипт нашёл файл в корне и завершился успешно: сообщил **0 зон с изменённой геометрией или положением штампа**, затем успешный `RebuildView`. Проверка записанных параметров 471 зоны до этого также завершилась успешно: **471 проверена, 0 несоответствий**. Поэтому первая ошибка не означает, что последующая проверка геометрии осталась невыполненной.

Полный обход GDL-параметров всех 1427 зон не завершился. Следующая попытка подсчёта также завершилась ошибкой. Дальнейшая выборочная проверка других зон не заменяет полный обход. Это различие нужно явно сохранять в отчёте, даже если целевые 471 изменения и их геометрия проверены отдельно.

## Исправления приложения

1. **Отдельная рабочая папка чата в профиле приложения.** История привязана к ID проекта и чата. Python, файловые инструменты, промежуточные JSON, скрипты, журналы, изображения, каталог API и вложения по умолчанию работают в этой папке. Два чата одного проекта не перезаписывают одинаковые `work/data.json` друг у друга. Данные сохраняются после завершения работы и перезапуска приложения.
2. **Явное обращение к исходникам проекта.** У файловых инструментов есть `scope: session | project`, по умолчанию `session`. Для Python доступны `ARCHI_PROJECT_DIR`, `ARCHI_WORK_DIR`, `ARCHI_PROJECT_ID`, `ARCHI_SESSION_ID` и `ARCHI_LEGACY_DIR`. Итоговый документ в папку проекта записывается по запросу пользователя; экспорт переписки открывает выбор места сохранения. Python остаётся обычным локальным процессом, а не файловой песочницей: это организация путей и поведения агента, не запрет всех возможных абсолютных путей.
3. **Совместимость старых чатов.** Служебная `.archi` копируется в профиль без удаления оригинала; сессии импортируются отдельно и связываются с зарегистрированным проектом. Повторный запуск не перезаписывает более новые данные. Старые результаты и изображения открываются через совместимый поиск. Непомеченные промежуточные файлы в корне проекта и `work/` автоматически не удаляются и не перемещаются.
4. **Причина остановки отдельно от вывода.** Исполнитель сохраняет код завершения, причину (`completed`, `exit-error`, `timeout`, `cancelled`, `start-error`, `log-error`), длительность, stderr и полный журнал. В краткую ошибку попадает исключение Python или явная причина остановки. Обычный stdout не используется как описание сбоя. В большом выводе сохраняются начало и конец, чтобы финальное исключение оставалось видно.
5. **Управляемый лимит и корректное восстановление.** По умолчанию остаётся 300 секунд; агент может обоснованно задать до 1800 через `timeout_seconds`. Инструкции требуют небольших партий, сохранения прогресса и проверки реальных путей. Тайм-аут и отмена помечают результат как потенциально неизвестный; изменения автоматически не повторяются. Нулевой код процесса сам по себе не считается доказательством успешной проверки данных.

## Расположение данных

```text
%APPDATA%/Archi/
  settings.json
  projects/<projectId>/
    sessions/<sessionId>.json
    workspaces/<sessionId>/
      attachments/
      work/                       # создаёт агент при необходимости
      .archi/
        api/
        results/<sessionId>/
        scripts/                  # .py и полный .log
        images/
        tmp/
    legacy/.archi/                # копия прежних служебных файлов
    migration.json
```

При переопределении профиля используется выбранный каталог вместо `%APPDATA%/Archi`. Папка проекта сохраняет исходники и явно запрошенные пользователем итоговые материалы. Старые служебные файлы остаются резервной копией; удалять их без отдельного решения пользователя приложение не будет.
