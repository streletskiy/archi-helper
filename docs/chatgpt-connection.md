# Подключение ChatGPT

В настройках провайдеров нажмите «Продолжить с ChatGPT», войдите в браузере и разрешите использование подписки. Подключение предназначено для открытого локального приложения; доступность определяется OpenAI и аккаунтом. Согласно документации OpenAI на 21 октября 2026 года, этот сценарий доступен подходящим аккаунтам Plus и Pro. Это отдельное подключение от OpenAI API с ключом.

После входа приложение выбирает подключённый аккаунт и запрашивает его актуальные модели. В списке показываются только модели с `visibility: list`, под названием `display_name`, в порядке сервера. Каталог обновляется при запуске, переключении аккаунта и по кнопке обновления. Набор моделей и параметры рассуждения не зашиты в приложение. Подписка и лимиты проверяются OpenAI; приложение не предполагает безлимит и не переключается автоматически на другой платный провайдер. Кнопка «Управление лимитами» открывает настройки использования в ChatGPT. Точные остатки квоты приложение не вычисляет.

Разные аккаунты и регистрации хранятся отдельно, даже если у них одинаковый email. Повторный вход проверяет идентификатор аккаунта, а не email. Чтобы добавить другой аккаунт, используйте соответствующую кнопку. При выходе приложение отзывает обновляемую сессию, удаляет access/refresh/ID-токены и оставляет регистрацию для повторного входа. Если отзыв не подтверждён из-за сети, запросы блокируются, а зашифрованные токены сохраняются для повторной попытки. Можно также отключить приложение в настройках ChatGPT.

## Протокол и хранение

- OAuth Authorization Code + PKCE S256, случайные `state` и `nonce`, временный HTTP callback на `127.0.0.1`.
- Первичная динамическая регистрация с `dynamic_agent_client`; выданный `client_id` сохраняется до обмена кода, в том числе для восстановления после его истечения. Идентификатор установки стабилен, непрозрачен и не содержит email.
- ID-токен проверяется библиотекой jose: подпись JWKS, issuer, audience, срок, nonce и прежний subject при повторном входе. Разрешение на использование подписки проверяется отдельно по выданным scopes.
- Секреты остаются в основном процессе Electron и шифруются Windows safeStorage. В интерфейс передаются только состояние подключения и имя аккаунта. Обновление токенов сериализуется; неизвестный результат обновления не повторяется автоматически.
- Используется только публичный `api.openai.com/v1/responses`, с `store: false`, `stream: true` и полной историей. Инструменты Archi Helper передаются в namespace и выполняются локально, через прежние разрешения приложения.
- Завершение подтверждается событием `response.completed`. Ошибки квоты, оборванный поток и незавершённые вызовы не запускают инструменты. Полные элементы reasoning сохраняются для продолжения, но не пересылаются другому аккаунту, подключению или провайдеру.

lumv и ручной ввод API-ключа продолжают использовать прежний совместимый API. Сервер lumv для этого подключения менять не требуется. Данные и учётные записи установленного Codex не используются.

## Проверка

`npm test` проверяет вход, выданный client ID, подпись и claims, повторный вход, разные регистрации с одним email, scopes, обновление, отзыв, ошибки сети, каталог моделей и потоковые ответы с инструментами. `npm run build` проверяет TypeScript и интерфейс; `npm run package` собирает Windows-приложение.

Проверка реального аккаунта требует входа владельца: подключиться, выбрать модель, отправить короткий запрос, выполнить безопасное чтение файла, перезапустить приложение, затем отключить доступ и убедиться, что новое сообщение требует повторного входа. Также проверить отключение со стороны ChatGPT Settings. Автоматические проверки используют тестовые токены и не подтверждают доступность конкретной подписки.
