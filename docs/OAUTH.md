# Подключение AI-провайдеров

Archi Helper поддерживает ручной Bearer API-ключ и вход через браузер по OAuth 2.0 Authorization Code + PKCE S256. Первая OAuth-конфигурация — lumv. Пользователь подтверждает аккаунт, кошелёк и месячный лимит в браузере; приложение получает access/refresh-токены без копирования ключа.

## Границы модулей

- `electron/provider-definitions.mjs` — публичные настройки: адрес API, OAuth endpoints, зарегистрированный client ID, scopes, путь/необязательный фиксированный порт callback, поля профиля и возможности каталога.
- `oauth-loopback.mjs` — временный сервер только на `127.0.0.1`, случайный порт, проверка state/Host/path, отмена и тайм-аут. Браузер получает только одноразовый код.
- `oauth-manager.mjs`, `oauth-config.mjs`, `oauth-store.mjs` — обмен кода, обновление, профиль, отзыв и шифрованное сохранение. Они не зависят от имени или домена провайдера.
- `provider.mjs` — OpenAI-compatible Chat Completions с инструментами и потоковой выдачей. Авторизация получается перед каждым запросом, в том числе внутри длительной задачи.

Секреты шифруются Electron safeStorage в основном процессе и не возвращаются через IPC. Адрес OAuth-подключения закреплён за определением провайдера. При ручной смене адреса старый API-ключ не переносится. Одновременные запросы используют одно обновление; запись настроек выполняется последовательно. После неоднозначного результата refresh требуется повторный вход, а не повтор использованного refresh-токена.

Удаление OAuth-провайдера сначала отзывает доступ на сервере. Если сервер недоступен, запросы блокируются локально, секрет сохраняется зашифрованным для повторного отзыва. Закрытие приложения само по себе не отзывает подключение. Установленный и portable-варианты поддерживаются; перенос профиля на другую Windows-учётную запись может потребовать нового входа из-за safeStorage.

## Следующие провайдеры

1. Зарегистрировать собственный public client и разрешённый loopback callback. Не использовать чужой client ID или токены другого приложения.
2. Добавить определение провайдера и scopes; client secret в desktop-приложении не используется. Дополнительные `audience`/`resource` задаются через `authorizationParameters`.
3. Сверить формат профиля, срок токенов, ротацию и правила отзыва. Нужны подтверждённые token/revocation endpoints.
4. Если API отличается от Chat Completions, добавить транспортный адаптер с тестами. Поле `adapter` отделяет этот контракт от OAuth; неизвестный адаптер отклоняется.

ChatGPT/Codex пока не добавлен как работающий провайдер: нужны зарегистрированный client ID, проверенные права использования и отдельная проверка API/адаптера. Основа поддерживает отдельный сервер авторизации, дополнительные параметры и фиксированный callback-порт. Справка: https://developers.openai.com/siwc/quickstart .

## Проверки

`npm test` проверяет callback/PKCE, отмену, отсутствие секретов в публичном состоянии, перезапуск, однократное параллельное обновление, отзыв и ручные ключи. Платные POST получают Idempotency-Key; повтор возможен только после явного 401 и один раз с тем же ключом. Сетевой обрыв отправленного POST автоматически не повторяется.
