# Разработка Archi Helper

## Локальный запуск

На машине разработчика нужны Windows x64, Git, Node.js 22.12+ и uv 0.11.26.

```powershell
git clone https://github.com/streletskiy/archi-helper.git
cd archi-helper
git switch dev
npm ci
npm run runtime
npm run build
npm start
```

Archicad нужен для проверки интеграции; интерфейс запускается и без него. Провайдер настраивается в самом приложении. Не добавляйте ключи в исходники или файлы проекта.

Для быстрой разработки запустите `npm run dev`, затем во втором терминале:

```powershell
$env:ARCHI_DEV_URL = 'http://127.0.0.1:5173'
npm start
```

Отдельный профиль задаётся аргументом `--archi-data-dir=путь` или переменной `ARCHI_DATA_DIR`. Каталог данных установленного приложения — `%APPDATA%\Archi`; это имя сохранено для совместимости. Резервируйте весь профиль, включая `Local State`.

История и служебные файлы хранятся в профиле: `projects/<projectId>/sessions/<sessionId>.json` и `projects/<projectId>/workspaces/<sessionId>/`. Рабочая папка каждого чата постоянная и отдельная; в ней находятся вложения, промежуточные файлы, `.archi/results`, `.archi/scripts`, `.archi/images`, `.archi/api` и временная папка Python. Относительные пути Python и файловых инструментов относятся к ней. Исходники проекта читаются с `scope: project` или через `ARCHI_PROJECT_DIR`; `ARCHI_WORK_DIR` указывает рабочую папку. В интерфейсе есть кнопка «Файлы чата», экспорт переписки предлагает выбрать файл.

При первом открытии старого проекта приложение копирует `.archi` в `projects/<projectId>/legacy/.archi` без каталога сессий, а сессии переносит копированием в новое хранилище. Исходные файлы не удаляются; более новые данные профиля не перезаписываются. Старые ссылки на результаты и изображения продолжают читаться из копии; для старых чатов файловые инструменты также умеют читать оставшиеся файлы проекта. В Python старые проектные пути нужно явно строить от `ARCHI_PROJECT_DIR`, а старые служебные — от `ARCHI_LEGACY_DIR`. Произвольные `work/` и JSON в корне автоматически не перемещаются и не удаляются: их принадлежность приложению нельзя надёжно определить. Хранилище не очищается автоматически при завершении запроса или обновлении, чтобы сохранялись продолжение работы и ссылки в истории.

`run_python` по умолчанию ограничен 300 секундами; `timeout_seconds` позволяет задать от 1 до 1800 секунд для обоснованной ограниченной работы. Результат отдельно содержит `termination`, `error`, `stderr`, `durationMs`, полный журнал и начало/конец большого вывода. Тайм-аут и остановка имеют `outcomeUnknown: true`; повторять изменения без проверки результата нельзя. Подробный [разбор исходного инцидента](docs/reports/session-files-and-python-errors.md) объясняет неверный путь и прежнюю диагностику тайм-аута.

## Проверки и сборка

```powershell
npm test
npm run build
npm run package
```

Команды запускают тесты, проверяют TypeScript и собирают интерфейс, затем создают установщик и portable EXE в `release`. Встроенная среда готовится командой `npm run runtime` из зафиксированного `vendor/requirements.lock`; системный Python не требуется.

NSIS использует ZIP (`useZip: true`, `differentialPackage: false`): файлы распаковываются сразу в каталог установки, без второго копирования всей среды Python из временной папки. Автообновления скачивают полный установщик; публичный релиз по-прежнему создаётся только тегом. Это увеличивает размер загрузки относительно 7z, но устраняет лишнюю запись тысяч файлов на диске.

Изменения агента проверяйте на отдельном тестовом PLN. В описании изменений указывайте сценарии проверки и ограничения. Не обещайте поддержку команды только потому, что она присутствует в каталоге.

## Ветки и релизы

- Создавайте рабочие ветки `feature/…` от `dev`, направляйте изменения в `dev`.
- Для выпуска обновите `version` в `package.json` и lock-файле, добавьте русские заметки в `docs/releases/<версия>.md` и запись в `changelog.md`.
- Перенесите проверенные изменения из `dev` в `main`. Дождитесь успешных проверок.
- Создайте тег на нужном коммите `main`: `git tag v0.2.0`, затем `git push origin v0.2.0`.

Workflow «Windows release» проверяет, что тег соответствует версии пакета и принадлежит истории `main`. Он собирает EXE, добавляет исходники PyMuPDF/MuPDF и SHA-256, затем публикует релиз. Персональные токены для обычного выпуска не нужны: используется ограниченный `GITHUB_TOKEN`.

Коммиты `main`, `dev` и pull request проходят только проверки. Windows EXE собираются только по релизным тегам; артефакты такой сборки хранятся в Actions 14 дней, опубликованные файлы остаются в Releases. Проверки веток не имеют прав публикации.

Автообновление использует стабильные GitHub Releases, `latest.yml` и установщик NSIS. Эти файлы публикуются вместе только после успешной сборки. Версию увеличивайте по SemVer; уже опубликованные релизы не заменяйте. Portable обновляется вручную. Цифровую подпись издателя можно добавить позже, сохранив appId и имя продукта.

## Структура

| Каталог | Содержание |
| --- | --- |
| `src` | Интерфейс React |
| `locales` | Общие словари RU/EN для интерфейса и Electron |
| `electron` | Окно, проекты, провайдеры, агент и MCP |
| `electron/knowledge` | [База проверенных приёмов для агентов](electron/knowledge/README.md), ограничения и порядок согласования |
| `vendor` | Исходники MCP, зависимости Python, лицензии |
| `scripts` | Подготовка среды, выпуск и графика |
| `assets/brand` | Редактируемые спрайты Aseprite 32×32 |
| `docs` | Проверки, релизы, скриншот |

Исходники персонажа уже включены; Aseprite не нужен для обычной сборки. Для повторной генерации установите Aseprite, клонируйте [Aseprite MCP](https://github.com/MalloyTheDev/aseprite-mcp) в `.cache/aseprite-mcp`, задайте `ASEPRITE_PATH` и запустите `node scripts/build-brand.mjs`.

Зависимости обновляйте отдельными изменениями с проверкой лицензий и переносимой среды. Встроенный PyMuPDF закреплён на 1.28.2: приложению нужны обработка и отрисовка PDF без дополнительных моделей анализа документов.


## Локализация

Пользовательские строки добавляйте одновременно в `locales/ru.json` и `locales/en.json` с одинаковыми ключами и параметрами подстановки. Вызывайте `t(key, values)`; не храните переведённые подписи в константах на уровне модуля. В исполняемом коде кириллицы быть не должно; русские тексты остаются в словарях и документации.

Язык сохраняется в настройках, при первом запуске определяется по языку Windows (для остальных языков используется английский). Системные инструкции и описания инструментов агента пишутся по-английски. Ответы, пояснения действий и отчёты должны следовать языку обращения пользователя.
