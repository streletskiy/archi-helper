# Разработка Archi Helper

## Локальный запуск

На машине разработчика нужны Windows x64, Git, Node.js 22.12+ и uv 0.11.26.

```powershell
git clone https://github.com/streletskiy/archi-helper.git
cd archi-helper
git switch dev
npm ci
npm run runtime
npm run build
npm start
```

Archicad нужен для проверки интеграции; интерфейс запускается и без него. Провайдер настраивается в самом приложении. Не добавляйте ключи в исходники или файлы проекта.

Для быстрой разработки запустите `npm run dev`, затем во втором терминале:

```powershell
$env:ARCHI_DEV_URL = 'http://127.0.0.1:5173'
npm start
```

Отдельный профиль задаётся аргументом `--archi-data-dir=путь` или переменной `ARCHI_DATA_DIR`. Каталог данных установленного приложения — `%APPDATA%\Archi`; это имя сохранено для совместимости. Резервируйте весь профиль, включая `Local State`.

История и служебные файлы хранятся в профиле: `projects/<projectId>/sessions/<sessionId>.json` и `projects/<projectId>/workspaces/<sessionId>/`. Рабочая папка каждого чата постоянная и отдельная; в ней находятся вложения, промежуточные файлы, `.archi/results`, `.archi/scripts`, `.archi/images`, `.archi/api` и временная папка Python. Относительные пути Python и файловых инструментов относятся к ней. Исходники проекта читаются с `scope: project` или через `ARCHI_PROJECT_DIR`; `ARCHI_WORK_DIR` указывает рабочую папку. В интерфейсе есть кнопка «Файлы чата», экспорт переписки предлагает выбрать файл.

При первом открытии старого проекта приложение копирует `.archi` в `projects/<projectId>/legacy/.archi` без каталога сессий, а сессии переносит копированием в новое хранилище. Исходные файлы не удаляются; более новые данные профиля не перезаписываются. Старые ссылки на результаты и изображения продолжают читаться из копии; для старых чатов файловые инструменты также умеют читать оставшиеся файлы проекта. В Python старые проектные пути нужно явно строить от `ARCHI_PROJECT_DIR`, а старые служебные — от `ARCHI_LEGACY_DIR`. Произвольные `work/` и JSON в корне автоматически не перемещаются и не удаляются: их принадлежность приложению нельзя надёжно определить. Хранилище не очищается автоматически при завершении запроса или обновлении, чтобы сохранялись продолжение работы и ссылки в истории.

`run_python` по умолчанию ограничен 300 секундами; `timeout_seconds` позволяет задать от 1 до 1800 секунд для обоснованной ограниченной работы. Результат отдельно содержит `termination`, `error`, `stderr`, `durationMs`, полный журнал и начало/конец большого вывода. Тайм-аут и остановка имеют `outcomeUnknown: true`; повторять изменения без проверки результата нельзя. Подробный [разбор исходного инцидента](docs/reports/session-files-and-python-errors.md) объясняет неверный путь и прежнюю диагностику тайм-аута.

Сессии без проекта используют отдельное служебное пространство профиля и собственные рабочие папки чатов. Архивирование хранит метку на проекте или сессии, не перемещая файлы. Удаление проекта затрагивает только его хранилище в профиле; исходная папка не удаляется. Черновики переключаемых чатов живут в памяти до закрытия приложения.

## Проверки и сборка

```powershell
npm test
npm run build
npm run package
```

Команды запускают тесты, проверяют TypeScript и собирают интерфейс, основной процесс Electron и нативный экран обновления, затем создают установщик и portable EXE в `release`. Для `npm start` сначала выполните `npm run build`: точка входа `electron/main.bundle.mjs` генерируется и не хранится в Git. Экран обновления собирается штатным компилятором .NET Framework 4 из Windows; дополнительная установка SDK не требуется. Встроенная среда готовится командой `npm run runtime` из зафиксированного `vendor/requirements.lock`; системный Python не требуется.

NSIS использует 7z/LZMA и дифференциальные обновления (`useZip: false`, `differentialPackage: true`). Вместе с установщиком обязательно публикуется `.exe.blockmap`; обновлятор использует сохранённый установщик и загружает изменившиеся блоки. При отсутствии старой карты блоков или кеша выполняется полная загрузка. Сжатие увеличивает время подготовки установщика, зато уменьшает размер скачивания. Публичный релиз создаётся только тегом.

Начиная с 0.2.19 NSIS получает встроенную среду отдельным `runtime.7z`. Перед тихим обновлением проверяются состав, размеры и SHA-256 всех её файлов. Совпавший каталог временно переименовывается на том же диске и возвращается после замены приложения; Python не удаляется и не распаковывается повторно. При несовпадении используется полная среда из установщика с обязательной проверкой после распаковки. Допускаются только дополнительные кеши `__pycache__/*.pyc`; ссылки, лишний код и отсутствующие файлы исключают повторное использование. При отказе установки обработчик пытается вернуть сохранённый каталог.

Архив среды записывается прямо в `resources` через `preCompressedFileExtensions: [".7z"]`, распаковывается сразу в конечный каталог и затем удаляется. Используются несолидный LZMA2 и словарь 1 МиБ; автоматические исполняемые фильтры отключены, поскольку поставляемый Nsis7z не поддерживает новый фильтр ARM64. Размер среды учитывается при проверке свободного места. `npm run package` собирает NSIS и portable последовательно: portable и `package:dir` сохраняют обычную готовую среду. Не собирайте NSIS и portable одним вызовом electron-builder. При изменении упаковки проверяйте весь установленный состав, повреждённую среду и план дифференциальной загрузки. Методика и результаты — в [отчёте](docs/reports/update-install-0.2.19.md).

Простой файл статуса `applying/complete/error` сохраняет совместимость со старым экраном. Дополнительный `.progress.json` содержит текущую операцию; проверка среды добавляет процент по количеству файлов и оценку времени этапа. Это не процент всего обновления. NSIS не отдаёт точный внешний счётчик распаковки: для этого этапа показываются операция и прошедшее время, без выдуманного процента. Устаревшая оценка времени скрывается. Нативное окно всегда следует теме Windows независимо от темы основного приложения.

В пакет включается только настоящий каталог CPython 3.13.7; ссылка `cpython-3.13` от uv исключена, чтобы архиватор не создавал вторую копию Python. При обновлении Python синхронно изменяйте версию в `scripts/prepare-runtime.mjs` и путь фильтра `build.extraResources` в `package.json`. Кеш Python, отладочные карты JavaScript, заголовки/библиотеки разработки MuPDF и справочник PyWin32 не поставляются. Лицензии и метаданные зависимостей сохраняются. Chromium включает только `en-US` и `ru`; зависимости интерфейса устанавливаются для сборки и входят в Vite bundle, без повторной копии в `app.asar`.

Основной процесс и его зависимости собираются esbuild в один ESM-файл; дерево `node_modules` в приложение не включается. `scripts/build-main.mjs` сохраняет лицензии вошедших зависимостей в `resources/licenses/node`. Проверяйте не только сборку, но и запуск упакованного MCP: динамические загрузки библиотек могут требовать явного включения в bundle.

Список чатов использует восстанавливаемый `session-index.json` в хранилище проекта. Канонические JSON сессий остаются источником данных; изменение, добавление и удаление файлов обнаруживаются при чтении списка. Отсутствующий или повреждённый индекс пересоздаётся. Удаление индекса допустимо только при закрытом приложении; удалять сессии для сброса кеша не нужно.

Замеры производительности: после `npm run package` выполните `node --expose-gc scripts/benchmark-performance.mjs after all`. Команда создаёт отдельный синтетический профиль в `.cache/performance-0.2.10`, не обращается к реальному провайдеру и сохраняет JSON с результатами там же. Методика сравнения с 0.2.9 и ограничения описаны в [отчёте](docs/reports/performance-0.2.10.md).

Изменения агента проверяйте на отдельном тестовом PLN. В описании изменений указывайте сценарии проверки и ограничения. Не обещайте поддержку команды только потому, что она присутствует в каталоге.

Не ссылайтесь на реальные пользовательские проекты или сессии в коде, справочнике, примерах, отчётах, коммитах и релизах. Названия, GUID, пути, даты работ, количества элементов и результаты операций заменяйте обобщёнными выводами и явно синтетическими примерами. Удаления одного имени недостаточно, если остальные сведения позволяют узнать исходный проект. Перед публикацией проверьте diff, изображения и содержимое сборки.

## Ветки и релизы

- Создавайте рабочие ветки `feature/…` от `dev`, направляйте изменения в `dev`.
- Для выпуска обновите `version` в `package.json` и lock-файле, добавьте русские заметки в `docs/releases/<версия>.md` и запись в `changelog.md`.
- Перенесите проверенные изменения из `dev` в `main`. Дождитесь успешных проверок.
- Создайте тег на нужном коммите `main`: `git tag v0.2.0`, затем `git push origin v0.2.0`.

Workflow «Windows release» проверяет, что тег соответствует версии пакета и принадлежит истории `main`. Он собирает EXE, добавляет исходники PyMuPDF/MuPDF и SHA-256, затем публикует релиз. Персональные токены для обычного выпуска не нужны: используется ограниченный `GITHUB_TOKEN`.

Коммиты `main`, `dev` и pull request проходят только проверки. Windows EXE собираются только по релизным тегам; артефакты такой сборки хранятся в Actions 14 дней, опубликованные файлы остаются в Releases. Проверки веток не имеют прав публикации.

Автообновление использует стабильные GitHub Releases, `latest.yml` и установщик NSIS. Эти файлы публикуются вместе только после успешной сборки. Версию увеличивайте по SemVer; уже опубликованные релизы не заменяйте. Portable обновляется вручную. Цифровую подпись издателя можно добавить позже, сохранив appId и имя продукта.

## Структура

| Каталог | Содержание |
| --- | --- |
| `src` | Интерфейс React |
| `locales` | Общие словари RU/EN для интерфейса и Electron |
| `electron` | Окно, проекты, провайдеры, агент и MCP |
| `electron/knowledge` | [Markdown-база знаний](electron/knowledge/README.md): промпты, общие процедуры, уточнения версий; личные записи хранятся отдельно в профиле |
| `vendor` | Исходники MCP, зависимости Python, лицензии |
| `scripts` | Подготовка среды, выпуск и графика |
| `assets/brand` | Редактируемые спрайты Aseprite 32×32 |
| `docs` | Проверки, релизы, скриншот |

Исходники персонажа уже включены; Aseprite не нужен для обычной сборки. Для повторной генерации установите Aseprite, клонируйте [Aseprite MCP](https://github.com/MalloyTheDev/aseprite-mcp) в `.cache/aseprite-mcp`, задайте `ASEPRITE_PATH` и запустите `node scripts/build-brand.mjs`.

Зависимости обновляйте отдельными изменениями с проверкой лицензий и переносимой среды. Встроенный PyMuPDF закреплён на 1.28.2: приложению нужны обработка и отрисовка PDF без дополнительных моделей анализа документов.


## Локализация

Пользовательские строки добавляйте одновременно в `locales/ru.json` и `locales/en.json` с одинаковыми ключами и параметрами подстановки. Вызывайте `t(key, values)`; не храните переведённые подписи в константах на уровне модуля. В исполняемом коде кириллицы быть не должно; русские тексты остаются в словарях и документации.

Язык сохраняется в настройках, при первом запуске определяется по языку Windows (для остальных языков используется английский). Системные инструкции и описания инструментов агента пишутся по-английски. Ответы, пояснения действий и отчёты должны следовать языку обращения пользователя.
