# Проверяемое назначение слоя

Перед сменой слоя прочитайте текущий `layerIndex` элемента и актуальный каталог слоёв. Получайте индекс из `GetLayers[].index`, а не из позиции записи в массиве и не из GUID атрибута. Проверяйте ошибки каждой записи каталога и полноту выборки. Сохраните исходный индекс для восстановления.

В `SetDetailsOfElements` слой находится в `elementsWithDetails[].details.layerIndex`. Явно синтетический пример структуры, не ссылка на существующий элемент или слой:

```json
{"elementsWithDetails":[{"elementId":{"guid":"00000000-0000-4000-8000-000000000004"},"details":{"layerIndex":7}}]}
```

## Исходный и целевой слои проверяются отдельно

Читайте `isLocked` обоих слоёв непосредственно перед изменением. В синтетическом испытании назначение Morph **в** заблокированный слой прошло успешно. Последующая попытка перевести этот элемент **из** заблокированного слоя вернула `executionResults[].success:false` с ошибкой; чтение подтвердило прежний индекс. Блокировка только целевого слоя не объясняет любой отказ смены слоя.

Не снимайте намеренную блокировку существующего слоя автоматически. Сначала согласуйте необходимое изменение состояния; при разрешённом разблокировании повторно прочитайте его результат. Для восстановления сохраните исходные состояния слоёв и самого элемента. Переход в заблокированный слой может потребовать отдельного согласованного разблокирования для последующего возврата.

## Подтверждение результата

После записи проверьте каждый `executionResults`, затем свежим `GetDetailsOfElements` прочитайте `layerIndex` каждой цели. Сопоставьте прочитанный индекс с актуальным каталогом. В отдельном синтетическом случае команда приняла индекс, отсутствовавший в прочитанном каталоге, и вернула его при чтении. Поэтому `success:true` вместе с совпавшим числом не доказывает корректность ссылки на слой.

При ошибке отделите применённые операции от неудачных и неопределённых; не повторяйте весь пакет. После разрешённого устранения препятствия повторяйте только нужные присваивания. Восстановление исходного индекса и состояния блокировки также проверяйте чтением; общий порядок — в `model-edit-verification`.

## Границы подтверждения

Проверено 2026-11-02 в отдельном синтетическом PLN: Archicad 27, build 5003, Tapir 1.7.3. Испытаны назначение существующего индекса, индекс вне прочитанного каталога и переходы собственного тестового Morph между новыми тестовыми слоями. Заблокированный исходный слой дал отказ; после разблокирования исходный индекс восстановлен. Оба тестовых слоя оставлены разблокированными, настройки ранее существовавших слоёв сравнены с исходным снимком.

Основание — поставляемые схемы `SetDetailsOfElements`, `GetLayers`, `GetDetailsOfElements` и независимое сопоставление полных ответов. Teamwork, другие типы элементов, версии и причины отказа отдельно не проверены. Этот опыт не устанавливает причину исторического сбоя с неизвестным значением индекса.
