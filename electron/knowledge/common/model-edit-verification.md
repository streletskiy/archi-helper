# Пакетные изменения и проверка геометрии

Основание — поставляемые схемы Tapir `command_definitions.js` и `common_schema_definitions.js`. Это правила подготовки и проверки запросов, без нового интеграционного прогона в PLN. Перед применением получите схему текущего подключения: наличие поля в поставляемом каталоге не гарантирует его поддержку установленным дополнением. Изменения выполняются в пределах разрешённой пользователем задачи и режима приложения.

## До изменения и после частичного сбоя

Сохраните локально исходные параметры и точный список целевых элементов. Если задача касается выделения, прочитайте `GetSelectedElements`; пустое выделение не разрешает заменять его всеми элементами проекта. Идентификаторы переносите программно из ответа API.

Проверьте каждую запись запроса и начните с ограниченной пробы. После вызова разберите все `executionResults`: явный `success:false` или `error` — сбой, отсутствие результата или явного признака успеха — неопределённость. Сопоставляйте ответы с входом только по документированному порядку или идентификаторам. Несовпадение длины ответа с запросом нельзя скрывать через `zip`, который обрежет хвост.

`AssertionError`, другое исключение Python, отмена или тайм-аут не откатывают уже выполненные вызовы. Нельзя считать пакет атомарным без отдельной гарантии команды. Сначала повторно прочитайте состояние целей, отделите применённые изменения от неудачных и неопределённых. Повторяйте только необходимые операции; после создания сначала найдите уже созданные элементы, чтобы не получить дубликаты. Для восстановления используйте локальный снимок и проверяйте результат восстановления чтением.

## Создание: идентификатор или ошибка

У `CreateWalls` ответ — `elements` (`ElementIdsOrErrors`); у `CreateBuildingMaterials` — `attributeIds` (`AttributeIdsOrErrors`). В записи находится `elementId`/`attributeId` либо `error`, без обязательного `success`. Здесь проверяйте эти массивы, а не `executionResults`.

Явно синтетический ответ:

```json
{"elements":[{"elementId":{"guid":"00000000-0000-4000-8000-000000000003"}},{"error":{"code":-1,"message":"Synthetic failure"}}]}
```

Разделите успешные ID, ошибки и неопределённые записи; не теряйте исходный ответ. Перед повтором прочитайте уже созданные элементы. Проверены только поставляемые схемы и синтетический JSON, без изменения PLN.

## Перекрытия: форма записи и сохранение геометрии

У `ModifySlabs` аргумент `slabsWithDetails` — массив объектов. Каждая запись содержит `elementId`, а изменяемые свойства находятся **в той же записи**. Строки с именами полей не являются отдельными элементами массива. Ошибка «строка вместо объекта» может указывать на неверную сборку массива, а не на тип самого материала.

Синтетический пример построения запроса; `slab_id` здесь означает объект идентификатора, ранее прочитанный через API:

```python
record = {"elementId": slab_id}
record["topMaterial"] = {"overridden": False}
payload = {"slabsWithDetails": [record]}
```

`topMaterial`, `sideMaterial`, `bottomMaterial` имеют тип `OverriddenMaterial`: объект с `overridden` и, для выбранной поверхности, `attributeId`. Значение `attributeId` — объект `{guid}`, полученный из каталога атрибутов. `overridden:false` возвращает наследуемую поверхность; оно не меняет строительный материал. Не переносите сюда числовой индекс из параметра GDL: это другой контракт API.

В поставляемой схеме `polygonOutline` заменяет контур **вместе с отверстиями**: для сохранения отверстий передайте их явно. Если меняются только отверстия, поле `holes` можно передать без контура; пустой массив очищает отверстия. Перед вызовом сверьте эту семантику с текущей схемой. `thickness` действует на однородное перекрытие; у многослойного толщина определяется композитом. Не переводите конструкцию в `Basic` только ради изменения числа без согласованного изменения конструкции.

## Крыши: граница контракта ModifyRoofs

Поставляемое описание `ModifyRoofs` ограничивает команду многоплоскостными крышами. Перед подготовкой запроса прочитайте `GetDetailsOfElements`: класс находится в `detailsOfElements[].details.roofClass`, допустимые значения — `SinglePlane` и `MultiPlane`. Отсутствующий класс не считайте `MultiPlane`. Поддержка `pivotLine` и `angle` при создании через `CreateRoofs` не расширяет контракт изменения: в `ModifyRoofs` этих полей нет.

Вход `ModifyRoofs` — `roofsWithDetails`, каждая запись содержит `elementId` и изменяемые поля на одном уровне. Ниже явно синтетический JSON для проверки структуры; идентификатор не относится к существующему элементу:

```json
{"roofsWithDetails":[{"elementId":{"guid":"00000000-0000-4000-8000-000000000001"},"level":1.25}]}
```

Валидная структура не проверяет класс крыши по GUID и не подтверждает применение команды. Для `SinglePlane` найдите отдельный документированный путь текущей версии либо согласуйте правку в интерфейсе. Ошибка ограничения класса не устраняется повтором того же пакета; удаление и пересоздание крыши или замена на Morph требуют отдельного согласования.

Для подходящего класса сохраните исходные значения, проверьте каждый `executionResults` и повторно прочитайте изменённые параметры. При частичном результате используйте порядок восстановления выше. Здесь проверены только описание команды и синтетический JSON по поставляемой схеме; изменение модели и сохранение геометрии в отдельном PLN не проверялись.

## Материал и форма — отдельные проверки

У `ModifyMorphs` свойства `buildingMaterialId` и `surfaceId` задают атрибуты, а не новую геометрию. Поле `body` заменяет геометрию целиком; это не частичная правка граней. Не отправляйте неполное тело для изменения цвета. Материал элемента и поверхности отдельных граней проверяйте отдельно, если API предоставляет оба уровня.

После изменения прочитайте параметры и геометрию. `Get3DBoundingBoxes` помогает проверить габариты и положение, но не доказывает наличие отверстий или правильность ступеней. При доступности `Get3DGeometryOfElements` проверьте каждый результат `geometries3D`, ошибки, тела и нужные контуры. Пустые `bodies` могут означать отсутствие твёрдого тела или фильтрацию в 3D-виде. Отсутствующий `surfaceId` грани не обязательно означает ошибку: поверхность может быть определена GDL, а не атрибутом проекта.

Снимок правильного вида дополняет проверку, но смена проекции или удачный ракурс не исправляют геометрию. В итоговом ответе различайте принятый запрос, прочитанные параметры, проверенную форму и оставшиеся ограничения. Успех инструмента сам по себе не подтверждает выполнение задачи.
