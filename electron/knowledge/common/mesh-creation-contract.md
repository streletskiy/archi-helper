# Рельеф Mesh: подготовка запроса CreateMeshes

Статья помогает собрать JSON для создания рельефа через Tapir. Сначала получите схему `CreateMeshes` из каталога текущего подключения. Изменения допустимы только в пределах разрешённой пользователем задачи; статья не разрешает заменять или удалять существующий рельеф.

## Форма запроса

В поставляемой схеме корень запроса — `meshesData`, массив объектов. В каждой записи обязателен `polygonCoordinates`: массив не менее чем из трёх объектов `Coordinate3D` с числовыми `x`, `y`, `z`. Поле `level`, если передаётся, задаёт опорный уровень Z по описанию команды.

Необязательный `sublines` — массив объектов `MeshSubline`; внутри каждого обязателен массив `coordinates` с объектами `Coordinate3D`. Список точек непосредственно в `sublines` не соответствует этому контракту. В схеме создания у `sublines` есть `minItems:1`: если подлинии не передаются, опустите поле, а не подставляйте пустой массив. Не переносите сюда ограничения одноимённого поля другой команды.

У `skirtType` допустимы только `SurfaceOnlyWithoutSkirt`, `WithSkirt`, `SolidBodyWithSkirt`. Это значения перечисления, а не обещание конкретного геометрического результата. Тела `geometries3D[].bodies` из `Get3DGeometryOfElements` не являются записями `meshesData`: поля и вложенность у чтения 3D-геометрии и создания Mesh различаются.

Явно синтетический JSON для проверки структуры, без отправки в Archicad:

```json
{"meshesData":[{"level":0,"skirtType":"SurfaceOnlyWithoutSkirt","polygonCoordinates":[{"x":0,"y":0,"z":0},{"x":4,"y":0,"z":0},{"x":4,"y":3,"z":0},{"x":0,"y":3,"z":0}],"sublines":[{"coordinates":[{"x":1,"y":1,"z":0.2},{"x":2,"y":1,"z":0.3}]}]}]}
```

## Проверка и восстановление

Перед вызовом проверьте каждую запись по текущей схеме. Валидный JSON не подтверждает допустимость контура, высот, подлиний или триангуляции. Для утверждения о форме нужен отдельный синтетический PLN и независимое чтение полученной геометрии.

Ответ `CreateMeshes` содержит `elements` (`ElementIdsOrErrors`): проверяйте каждую запись на `elementId` либо `error`, сопоставляйте число результатов с запросом. Здесь нельзя ожидать обязательный `executionResults` или считать отсутствие исключения доказательством создания. Разбор частичного результата описан в `model-edit-verification`.

При ошибке структуры исправьте поля и вложенность по каталогу. Если вызов уже был отправлен и результат частичный или неизвестный, сначала прочитайте состояние и найдите созданные элементы; повторять весь запрос без такой проверки нельзя. Не удаляйте исходный рельеф ради обхода ошибки. Восстановление изменений требует сохранённого исходного состояния и проверки чтением.

## Синтетическая проверка чтением

На Archicad 27, build 5003, Tapir 1.7.3 отдельно проверены простые синтетические рельефы с `level:0`: без подлиний и с заданными подлиниями. После создания `GetDetailsOfElements` вернул соответствующие контур и `sublines[].coordinates`; при сравнении контура учитывалась возможная повторная замыкающая вершина. В свежем `Get3DGeometryOfElements` найдены заданные точки подлиний с их высотами. Пустой `sublines` отклонён оболочкой MCP по схеме до вызова команды; дополнительный рельеф не появился.

Это проверка передачи параметров и наличия точек в прочитанной геометрии. Она не доказывает сохранение произвольной исходной поверхности, правильность всей триангуляции или универсальную интерпретацию `skirtLevel`. Одно совпавшее `skirtType` не заменяет сравнение геометрии. Пример JSON выше проверен по схеме; интеграционная проверка использовала отдельные синтетические данные.

## Копия по данным чтения

Для проверяемой копии сначала прочитайте параметры Mesh через `GetDetailsOfElements`. Собирайте новую запись `meshesData` только из полей, разрешённых текущей схемой `CreateMeshes`: не отправляйте весь объект ответа с его служебными полями и не заменяйте контур и подлинии сырыми телами `geometries3D`. Полные массивы координат переносите программно; отдельно сохраните исходный элемент и настройки. При согласованном горизонтальном сдвиге копии изменяйте координаты контура и всех подлиний согласованно, сохраняя Z и опорный уровень.

В отдельном синтетическом случае копия неплоского рельефа по прочитанным параметрам после компенсации горизонтального сдвига совпала с исходником по всем прочитанным вершинам, граням с их поверхностями, контуру и подлиниям. Это сравнение экспорта одной простой конфигурации, а не гарантия копирования произвольного Mesh с отверстиями, другой юбкой или иной триангуляцией. Контроль каждой записи создания и чтение новой геометрии остаются обязательными.

## Границы подтверждения

Проверка 2026-11-02 включает поставляемые определения Tapir, помеченные `1.7.2`: `CreateMeshes` (версия команды `1.1.9`), `Coordinate3D`, `MeshSubline`, `MeshSkirtType`, `ElementIdsOrErrors`, независимые синтетические JSON и описанный выше отдельный синтетический PLN. Корректная структура принята валидатором; неверная вложенность, пустой `sublines` и недопустимое перечисление отклонены. [Документация Tapir](https://enzyme-apd.github.io/tapir-archicad-automation/archicad-addon/) описывает команды дополнения в пространстве `TapirCommand`; доступность и контракт сверяйте с установленной версией. Прочие сочетания Archicad/build/Tapir и общее восстановление Mesh из тел `geometries3D` здесь не проверены.
