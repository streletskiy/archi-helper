# Возможности Archicad: версии и быстрый выбор инструментов

Здесь собраны общие технические правила. Границы ранее проверенных возможностей указаны отдельно для каждой версии. Статья не заменяет текущие `TestConnection` и каталог схем.

## Область проверки

Наблюдения вынесены в `versions/25` и `versions/27`. Общие маршруты ниже не обещают поддержку на любой версии: сверяйте текущее подключение и точную схему.

## Короткие маршруты

Перед вызовом получите полную схему по точному имени из `find_tools` или `get_api_catalog`. Имена ниже помогают выбрать команду, но не разрешают угадывать поля.

| Задача | Команда и проверенная особенность |
| --- | --- |
| Все макеты | `GetNavigatorItemTree`: `navigatorMapId="LayoutBook"`; параметра `map` нет |
| Состав конкретного набора публикации | `GetNavigatorItemTree`: `navigatorMapId="PublisherSets"` и точный `publisherSetName`; без имени возвращается только первый набор |
| Имена всех наборов | `GetPublisherSetNames`: встроенный `API.GetPublisherSetNames`, доступен через MCP; обходной вариант — документированный Graphisoft `GetPublisherSetNames()` |
| Базы макетов из навигатора | `GetDatabaseIdFromNavigatorItemId`: массив `navigatorItemIds` с вложенными `navigatorItemId`, а не одиночный аргумент |
| Открыть макет в AC25 | `ChangeWindow`: `windowType="Layout"`, `databaseId` из разрешённого идентификатора навигатора; вариант `navigatorItemId` требует AC27+ и на AC25 возвращал ошибку |
| Размеры и поля листов | `GetLayoutSettings`: `layoutDatabaseIds`; сверять ответ и ошибки для каждого элемента |
| Обзор и чтение | `get_project_overview`, `inspect_elements`: явная область, ограниченные пакеты, полные локальные результаты и частичное покрытие |
| Снимок вида | `capture_view`: свежий PNG, проверка файла и типа окна; показ и передача vision-модели выполняются автоматически |
| Экспорт PDF для проверки | `export_layout_package`: реестр, существующие PDF-наборы, локальный экспорт и сопоставление страниц; `audit_layout_text`: текст, координаты, словари и OCR |
| Проверяемые изменения | `apply_change_plan`: предварительный план абсолютных присваиваний, проверка исходных значений, запись и обратное чтение |
| Растровый запасной путь | `SaveCurrentWindowAsImage`: `imageFilePath`, а не придуманное имя файла; нужное разрешение результата обязательно проверять |

`PrintView` — печать, а не документированный универсальный PDF-экспорт. Не вызывайте его для получения PDF. `RunTapirCommand`, Python SDK и `ExecuteAddOnCommand` не добавляют отсутствующие команды. Версия определений в приложении и реально установленный Tapir могут различаться.

## Элементы, размещённые в элементах-владельцах

Для окон и дверей стены или подэлементов составного элемента используйте Tapir `GetConnectedElements`, если команда доступна в текущем подключении. Вход содержит обязательные `elements` — ссылки на владельцев в форме `{elementId:{guid}}` — и `connectedElementType` — тип искомых связанных элементов. Поле `elementType` не входит в схему этой команды; его имя из `GetElementsByType` сюда не переносится.

Явно синтетический запрос для проверки JSON-контракта:

```json
{"elements":[{"elementId":{"guid":"00000000-0000-4000-8000-000000000003"}}],"connectedElementType":"Window"}
```

При ошибке аргументов прочитайте текущую схему, исправьте имя поля и вложенность ссылок и повторите ограниченное чтение. После снятия оболочки MCP сначала проверьте верхнеуровневый `error`, затем `connectedElements` и вложенные массивы `elements`. Пустой список относится только к заданным владельцам и типу. Команда чтения не требует отката изменений модели.

Контракт проверен 2026-10-29 по поставляемым определениям Tapir 1.7.2 (`GetConnectedElements`, `Elements`, `ConnectedElementsOrError`) и синтетическим JSON. [Описание Tapir](https://enzyme-apd.github.io/tapir-archicad-automation/archicad-addon/) задаёт отдельное пространство `TapirCommand`; доступность и схему сверяйте с установленным дополнением. Новый интеграционный запуск в PLN и полнота поиска связанных элементов не подтверждались.

## Узкое чтение деталей элементов

Если у текущего `GetDetailsOfElements` есть `fields`, передавайте нужные поля верхнего уровня: `type`, `id`, `floorIndex`, `layerIndex`, `drawIndex`, `details`, `floorPlanPolygons`, `hotlinkId`. Например, свойства внутри `details` запрашиваются через `"details"`, а не через имя вложенного свойства вроде `"thickness"`. Пустой `fields` не проходит схему; отсутствие фильтра означает полный запрос.

Явно синтетический запрос для проверки структуры, без обращения к существующему элементу:

```json
{"elements":[{"elementId":{"guid":"00000000-0000-4000-8000-000000000002"}}],"fields":["type","details"]}
```

По описанию команды невыбранные поля не вычисляются; исключение `floorPlanPolygons` позволяет не запрашивать извлечение чертёжных примитивов. Это граница контракта, а не измеренный прирост скорости. В фильтрованном ответе отсутствующее невыбранное поле не означает ошибку: обязательные поля полной схемы ответа относятся к запросу без фильтра.

Сначала снимите оболочку MCP и прочитайте `detailsOfElements`. Если сведений недостаточно, расширьте `fields` по текущему каталогу и повторите чтение. Проверка структуры выполнена по поставляемым определениям `GetDetailsOfElements` / `ElementDetailsField` и [документации Tapir](https://enzyme-apd.github.io/tapir-archicad-automation/archicad-addon/) на синтетическом JSON; новый запуск в PLN и проверка геометрии не заявляются.

## Правильное чтение результатов

1. Полный MCP-результат хранится в `.archi/results`. Сначала возьмите `structuredContent`; если его нет, декодируйте JSON из `content[].text`. Обёртка MCP не является ответом самой команды.
2. У `GetNavigatorItemTree` корень — `navigatorItemTree`; узлы детей могут иметь оболочку `{"navigatorItem": ...}`. Снимайте её на каждом уровне, затем обходите `children`. В реестр включайте `LayoutItem`, отдельно храните путь подмножеств, `uiId`, имя и GUID.
3. GUID и databaseId переносите программно из полного сохранённого ответа. Не набирайте их вручную и не подменяйте один вид идентификатора другим без разрешения через API.
4. При переносе ссылок на элементы сохраняйте ровно ту вложенность, которую требует схема. Если `elementId` уже содержит объект `{guid}`, не оборачивайте его ещё раз в `elementId`. Проверяйте форму каждого элемента массива: корректный первый элемент не гарантирует корректности остальных.
5. Пустой список элементов в базе или активном макете не доказывает отсутствие содержимого либо его размещение на мастер-макете. Это граница конкретного запроса. Перейдите к PDF и проверке видимого содержимого.
6. Пустой ответ публикации не доказывает создания файлов. Проверьте реальные PDF, страницы и покрытие реестра. После тайм-аута публикация может продолжаться в Archicad: сначала проверьте состояние и файлы, не запускайте повторно.
7. Проверяйте каждый `executionResults`: `success:false` или вложенный `error` означает неудачу операции, даже если оболочка MCP не содержит `isError`. Перед повтором отделите уже применённые изменения и прочитайте фактическое состояние. Для библиотечных частей, окон и параметров GDL используйте `library-parts-gdl`.

Все изменения модели, сохранение PLN и специальные приёмы сохраняют свои требования согласования. Исторические наблюдения не дают разрешения изменять текущий проект.
