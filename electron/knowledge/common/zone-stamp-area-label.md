# Изменение надписи площади в существующем штампе зоны

Идентификатор: `zone-stamp-area-label`. Требуется явное одобрение пользователя.

## Что меняется

Приём переключает существующий штамп зоны на пользовательский текст, например `3,38 м²`. Контур зоны, её расчётная площадь, положение и поворот штампа должны сохраниться. Это замена **отображаемой надписи**, а не исправление фактической площади. Расчётные площади в спецификациях от неё не меняются. Сводные марки квартир, если это отдельные элементы `Text`, требуют отдельной операции и согласованного объёма работ.

Приём проверен на конкретном штампе в пользовательском файле. Значение `13` нельзя переносить на другой библиотечный штамп без проверки его параметров и смысла этого значения. Имя и версия библиотечного штампа в исходной записи не указаны: совпадения названий параметров недостаточно для обещания совместимости.

## Согласование до записи

Объясните пользователю, что изменится только надпись, а расчётные площади и спецификации сохранятся. Покажите текущие и целевые строки, список зон и количество изменений. Получите **явное одобрение именно этого способа и объёма**. Общий запрос «исправить площади», полный доступ, наличие статьи или одобрение изменения контура не являются таким согласием. Если пользователь уже явно одобрил этот способ для перечисленных зон и значений, учитывайте это согласование; при расширении объёма получите новое.

Передавайте `knowledge_id: "zone-stamp-area-label"` в каждый изменяющий вызов `call_archicad` или `run_python`, использующий этот приём, включая скрипты с данными из файлов. Приложение показывает подтверждение и в режиме полного доступа. В `purpose` укажите смысл замены и согласованный объём на языке пользователя; аргументы должны содержать конкретные зоны и значения. Не обходите отказ другим инструментом, Python, прямым HTTP или отдельным скриптом. В режиме чтения разрешены только изучение и подготовка предложения.

## Подготовка

1. Проверьте соединение и имя проекта. Откройте **план этажа**, а не макет: на макете `GetElementsByType` может вернуть только размещённый чертёж.
2. Найдите нужную зону по данным текущего проекта и проверьте её GUID. Не используйте исторический GUID из примера как текущую цель.
3. Через каталог подключения проверьте наличие и полные схемы `GetGDLParametersOfElements`, `SetGDLParametersOfElements`, `RebuildView` и доступных команд чтения геометрии и положения штампа.
4. Сохраните исходные четыре параметра, `ROOM_AREA`, `ROOM_NET_AREA`, контур, положение и поворот штампа в локальный журнал. Фиксируйте фактические поля поддерживаемого API, не придумывайте названия. Если необходимые данные или визуальная проверка недоступны, сообщите об этом и не переходите к массовой записи.

Чтение параметров через обнаруженную команду:

```json
{
  "name": "GetGDLParametersOfElements",
  "arguments": {
    "elements": [
      {"elementId": {"guid": "GUID_НУЖНОЙ_ЗОНЫ"}}
    ]
  }
}
```

Это пример имени команды и её аргументов; для `call_archicad` используйте точный ключ инструмента из `find_tools`. Подставьте проверенный GUID. Параметры находятся в `gdlParametersOfElements[0].parameters`. При нескольких зонах сопоставляйте результаты с входными элементами по фактической структуре ответа.

**Не отбрасывайте `HiddenFromScript` при чтении.** Не выводите `possibleValues`: огромные списки шрифтов скрывают полезные данные. Сохраните полный исходный ответ, а для анализа выберите имена, типы, значения и нужные флаги.

## Четыре изменения

| Параметр | Новое значение |
| --- | --- |
| `iOrder_1_temp` | `13` — пользовательский текст в проверенном штампе |
| `prefixCustomText` | Пустая строка, чтобы убрать префикс `СТ: ` |
| `contentCustomText` | Согласованная строка, например `3,38 м²` |
| `iOrder_1` | Копия исходного массива конкретной зоны, в которой изменён только первый элемент на `13` |

Например, `[4,11,11,11]` становится `[13,11,11,11]`. Длину массива и все остальные элементы сохраняйте из конкретной зоны; не копируйте хвост массива из примера на другие зоны. Если параметр отсутствует, имеет другой тип, массив пуст или смысл `13` не подтверждён, остановите запись и исследуйте штамп. **Нужно задать и `iOrder_1_temp`, и массив `iOrder_1`.**

Ниже шаблон исторически применённой операции. GUID заменён на явный заполнитель, массив и строка иллюстративны:

```json
{
  "name": "SetGDLParametersOfElements",
  "arguments": {
    "elementsWithGDLParameters": [
      {
        "elementId": {"guid": "GUID_НУЖНОЙ_ЗОНЫ"},
        "gdlParameters": [
          {"name": "iOrder_1_temp", "value": 13},
          {"name": "prefixCustomText", "value": ""},
          {"name": "contentCustomText", "value": "3,38 м²"},
          {"name": "iOrder_1", "value": [13,11,11,11]}
        ]
      }
    ]
  },
  "knowledge_id": "zone-stamp-area-label",
  "purpose": "Заменить только надпись площади согласованной зоны; расчётная площадь и контур сохранятся"
}
```

`knowledge_id` и `purpose` — поля инструмента приложения, их не передают внутри аргументов Tapir. При вызове через `RunTapirCommand` вложите имя команды и её аргументы в `command` и `parameters` согласно найденной схеме; `knowledge_id` остаётся на верхнем уровне `call_archicad`.

## Проверка и переход к остальным зонам

Сначала выполните согласованную пробу **на одной зоне**, затем повторно прочитайте её GDL-параметры и исходные данные:

- `contentCustomText` точно совпадает с согласованной строкой, `prefixCustomText` пустой;
- `iOrder_1_temp` и первый элемент `iOrder_1` равны `13`, остальные элементы и длина массива не изменились;
- `ROOM_AREA` и `ROOM_NET_AREA` сохранили исходные значения;
- контур зоны, положение и поворот штампа не изменились.

Обновите вид обнаруженной командой:

```json
{
  "name": "RebuildView",
  "arguments": {"regenerate": true}
}
```

Визуально проверьте надпись на плане: правильная зона, строка, единицы, отсутствие лишнего префикса и изменения оформления. В исходном случае менять шрифты, перья и другие параметры оформления не потребовалось. Не заявляйте о визуальной проверке, если текущая модель не поддерживает изображения или изображение не получено.

К остальным согласованным зонам переходите после успешной проверки пробы. Формируйте изменения отдельно из исходных параметров каждой зоны. Сохраняйте журнал результата по каждому GUID и итоговые количества успешных, ошибочных и непроверенных операций. Частичный успех не является успехом всей партии. При неизвестном результате или тайм-ауте сначала прочитайте состояние, не повторяйте запись вслепую.

При расхождении остановите дальнейшие изменения. Для восстановления используйте сохранённые исходные значения всех четырёх параметров именно этой зоны и те же правила согласования. После восстановления повторите чтение и визуальную проверку. Не исправляйте расхождения изменением контура, `ROOM_AREA`, `ROOM_NET_AREA` или положения штампа. Не сохраняйте и не закрывайте проект без отдельного запроса пользователя.
