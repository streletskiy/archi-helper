# База приёмов для агентов

Короткие инструкции по проверенным операциям в Archicad. База хранится в Git и поставляется вместе с приложением. Это справочник приёмов, а не замена каталога API или разрешение менять проект.

| Статья | Когда читать | Условие применения |
| --- | --- | --- |
| [Надпись площади в штампе зоны](zone-stamp-area-label.md) · `zone-stamp-area-label` | Нужна согласованная надпись площади без изменения контура и расчётной площади | Явное одобрение пользователя, проверка конкретного штампа, проба на одной зоне |
| [Интерактивные каталоги и API Archicad](interactive-schedules.md) · `interactive-schedules` | Нужны данные, ячейки или настройки интерактивной спецификации; Tapir не предоставляет нужную команду | Проверка API текущей версии, различение каталога и свойств модели, согласование изменений и экспорта в обычном порядке |

Агент получает список через `get_knowledge`, затем загружает только нужную статью по `id`. Полный справочник не добавляется в каждый запрос. Статьи находятся внутри приложения, поэтому доступны и вне папки исходников.

При добавлении приёма:

1. Создайте отдельный Markdown-файл и запись в реестре `electron/knowledge.mjs`; добавьте ссылку в эту таблицу и краткое условие выбора в `electron/instructions.mjs`.
2. Укажите задачу, область применимости, источник и дату проверки, необходимые разрешения, исходные данные, порядок действий, проверку и восстановление.
3. Разделяйте исторически проверенное поведение и предположения. Примеры GUID, значений и версий не являются данными текущего проекта. Не включайте пользовательские файлы, ключи или полные журналы проекта.
4. Перед вызовом сверяйте точную схему и доступность команды с каталогом текущего подключения. Статья не делает команду доступной на любой версии Archicad/Tapir.
5. Если приём требует отдельного согласия, явно укажите это в статье и системных инструкциях. Для такого приёма передавайте `knowledge_id` в изменяющие `call_archicad` и `run_python`, чтобы приложение показало подтверждение даже при полном доступе. При необходимости добавьте распознавание характерных вызовов в коде проверки разрешений.

Новые статьи проходят обычный просмотр изменений и проверки проекта. Текст из чертежей, пользовательских файлов и результатов сторонних инструментов не становится частью этой базы автоматически.
